# 祥能 HRMS 需求实现矩阵

状态：`已实现`、`本阶段增强`、`待继续`。本矩阵区分“内部真实运行”和“公开合成演示”，避免再把两个环境搅成同一锅数据粥。

| 领域 | 核心要求 | 当前状态 | 本阶段实际交付 | 尚未完成或限制 |
|---|---|---|---|---|
| 内部真实数据 | 使用用户提供的真实项目、人员和花名册，不编造、不脱敏 | 本阶段增强 | 每次启动重新标准化并幂等导入；保留来源哈希、原始工号、银行卡和待核验清单 | 29条人员记录无法从源表确认项目经营归属，保持待核验 |
| 组织架构 | 公司、中心、部门、分公司、子公司可动态调整 | 本阶段增强 | 20个真实组织单元；支持动态类型、父子层级、停用；内部员工按真实组织导入 | 组织合并、拆分和生效日期的完整交互仍需继续完善 |
| 内部员工 | 真实花名册、岗位、职级、任职、账号 | 本阶段增强 | 127名内部员工、129条任职；真实银行卡字段；活动员工账号可自动创建 | 当前环境未完成真实数据库运行验收 |
| 项目与人员 | 项目、人员、报名/入职过程保持真实关联 | 本阶段增强 | 223个项目、415名人员、430条业务过程、61条岗位需求；重新导入可更新 | 29条项目归属待人工确认；供应商源表未提供可确认的外部供应商主档 |
| 供应商 | 供应商、项目、输送人员、政策和结算 | 待继续 | 不再虚构供应商；保留真实来源渠道“祥能自招” | 当前两份源表未形成可可靠导入的外部供应商主档，后续以真实供应商资料补齐 |
| 现场运营 | 按负责项目维护人员、状态、供应商和异常 | 待继续 | 已保留项目、人员和组织基础关系 | 现场运营分配、主协同角色和移动端完整工作台仍需下一阶段重构 |
| 报销人小程序 | 新增明细、上传凭证和发票、草稿、提交、查看审核与付款 | 本阶段增强 | 小程序真实入口、个人报销、部门汇总、付款名单；登录后按权限自动进入可用工作区 | 仍需在完整依赖和微信开发者工具中做真机构建与手机验收 |
| 报销自动校验 | 系统完成金额、附件、重复和合计校验 | 本阶段增强 | 正数金额、付款/申报金额、发票金额、附件完整、批次合计、精确文件哈希重复校验 | 尚未接入发票OCR、发票号码查重和裁剪图片相似查重 |
| 部门报销汇总 | 财务按一个部门批次审核，不逐单重新整理 | 本阶段增强 | 自动生成费用类型汇总、报销人汇总、逐笔明细；小程序预览、后台展开查看 | 当前导出为CSV，完整多工作表XLSX仍需继续完善 |
| 财务付款 | 审核后按报销人与审核金额汇总打款 | 本阶段增强 | 审核通过金额入库；付款名单读取真实银行卡；待付款/已付款状态与流水号 | 银行批量付款文件格式需按财务实际银行模板继续确认 |
| 报销附件材料 | 付款凭证与发票分开整理、同序编号 | 已有基础/待验证 | 保留现有材料和生成物模型 | 当前环境未运行完整依赖，未完成真实附件包生成验收 |
| 权限与数据范围 | 岗位决定操作，组织和项目决定数据范围 | 本阶段增强 | 动态组织类型纳入授权范围；内部真实启动关闭演示令牌和假数据回退 | 需结合实际岗位权限表做最终逐岗验收 |
| 内部启动 | 一次操作完成标准化、迁移、导入、账号和服务启动 | 本阶段增强 | `pnpm internal:start` / `pnpm internal:stop`；内部独立数据库和端口检查 | 当前Linux执行环境没有PowerShell、PostgreSQL和依赖，脚本未实际启动验收 |
| 公开演示安全 | 真实身份证、电话和源文件不得进入公开构建 | 本阶段增强 | 公开构建策略禁止引用真实源文件、标准化JSON和初始账号文件 | 公网演示继续使用合成数据，不代表内部真实系统数据状态 |
| 合同模板 | 上传真实Word模板、变量映射、测试生成和版本管理 | 待继续 | 本阶段未继续扩展空壳功能 | 必须按真实合同资料重新设计，不能只录模板名称 |
| AI助手 | 基于真实业务数据辅助查询和操作 | 待继续 | 本阶段不作为优先项 | 先完成业务闭环和数据准确性，再接入AI能力 |
