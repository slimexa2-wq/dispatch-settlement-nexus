# 祥能 HRMS 真实数据与报销闭环阶段验收报告

日期：2026-07-27

## 一、阶段范围

本阶段按照已确认原则实施：

- 使用公司真实数据，不脱敏、不编造；
- 数据只录入一次，后续环节自动复用；
- 系统完成确定性的校验、汇总、传递和状态联动；
- 优先完成小程序报销、部门汇总审核、财务付款名单与真实组织基础；
- 内部真实数据与公开合成演示严格隔离。

本报告不把整个HRMS所有模块宣称为最终完成。项目、供应商、现场运营、合同等模块仍需按同一原则逐步深化。

### 数据处理原则

- 内部员工保留源工号，并单独生成唯一技术编号，避免重复工号或 `#REF!` 导致记录丢失；
- 保留真实银行卡号用于报销付款名单；
- 同一源文件重新导入时更新确定性记录，不要求清库重录；
- 29条无法确认项目经营归属的记录保留在待核验清单，不自行补造；
- 当前两份经营源表没有形成可可靠识别的外部供应商主档，因此未虚构供应商。

## 三、组织架构基础

已实现：

- 动态组织单元类型：公司、领导、中心、部门、业务部门、分公司、子公司等；
- 真实父子层级导入，防止导入后组织树被拍平成同一级；
- MOC运营中心下属分公司和子公司按真实组织类型保留；
- 项目经营区域继续与内部组织架构分离；
- 组织类型进入岗位授权和数据范围解析；
- 组织节点支持停用，不通过删除抹掉历史。

仍需继续：组织合并、拆分、生效日期、影响预览和历史版本的完整后台交互。

## 四、报销闭环

### 员工小程序

已实现：

- “我的报销”真实入口；
- 发起报销、明细和附件、草稿、提交、状态查询；
- 查看申报金额、审核通过金额和付款状态；
- 管理角色按权限进入部门汇总或付款名单；
- 登录权限异步加载后自动切换到实际可用页面，不再停在隐藏或错误入口；
- 部门汇总卡直接展示费用类型汇总、报销人汇总和明细数量。

### 系统自动校验

已实现确定性校验：

- 明细金额为正整数分；
- 付款金额与申报金额勾稽；
- 发票金额满足当前规则；
- 付款凭证和发票附件完整；
- 当前提交和历史数据中的附件SHA256精确重复；
- 明细与批次合计一致；
- 审核金额不超过申报金额；
- 实际付款金额与审核金额一致；
- 部门批次只能包含同一真实组织、同一月份的数据。

### 部门与财务

已实现：

- 默认按部门汇总审核，而不是逐张个人单据作为主入口；
- 自动生成费用类型汇总；
- 自动生成报销人汇总；
- 自动生成逐笔费用明细；
- 财务审核金额写入数据库；
- 审核后生成报销人与审核金额付款名单；
- 付款名单读取真实内部员工银行卡；
- 部门汇总和付款名单可导出UTF-8 CSV；
- 部门批次有未解决问题或状态不一致时，系统禁止批量推进。

### 明确限制

当前没有完成：

- 从图片或PDF中OCR提取付款金额和发票字段；
- 按发票代码、号码联网查重；
- 对裁剪、截图或重新压缩图片进行相似查重；
- 银行专用批量付款文件；
- 部门三张表的多工作表XLSX导出；
- 在当前环境中生成真实附件打印包的端到端运行验收。

因此，本阶段的重复发票校验是“精确文件哈希重复”，不能夸大为完整发票智能识别。

## 五、内部启动与数据隔离

已实现：

- `pnpm internal:start`：检查源文件、标准化、迁移、幂等导入、账号创建和三端启动；
- `pnpm internal:stop`：根据进程状态文件统一停止服务；
- 内部数据库固定为独立数据库；
- 内部启动强制关闭管理后台演示会话；
- 内部启动强制关闭统一入口合成数据回退；
- 活动内部员工账号自动创建，已有账号不覆盖；
- 初始账号文件处于内部忽略目录；
- 公开构建策略禁止真实源表、真实标准化JSON和内部账号文件进入公开产物。

## 七、交付结论

本阶段已经把“真实数据基础 + 动态组织基础 + 小程序报销入口 + 部门汇总审核 + 财务付款名单”从空壳改为有明确输入、自动规则、状态流转、输出成果和测试约束的业务基础版本。

它仍不是整个祥能运营系统的最终完成版。后续应继续按相同原则完成：

1. 项目、供应商、现场运营和人员的真实协同闭环；
2. 招聘到入离职的信息自动传递；
3. 周报、供应商反馈和结算自动生成；
4. 合同模板真实文件上传、字段映射和生成；
5. 报销OCR、发票级查重和银行付款文件。
