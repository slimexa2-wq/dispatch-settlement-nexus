# 数据迁移中心操作手册

## 1. 适用范围

数据迁移中心用于把历史 Excel/CSV 数据按批次迁入 HRMS。当前标准模板覆盖：合同主体、内部组织、经营分公司、岗位、职级、项目、供应商、招聘与推荐政策、招聘需求、内部员工、派遣外包员工与候选人、工资条历史数据。

## 2. 推荐迁移顺序

1. 合同主体、组织架构、经营分公司；
2. 岗位、职级；
3. 项目、供应商；
4. 招聘与推荐政策、招聘需求；
5. 内部员工、派遣外包员工与候选人；
6. 工资条历史数据；
7. 通过账户中心批量开通账号，通过权限中心开通角色和数据范围。

父级主档必须先导入。系统不会为不存在的项目、供应商、岗位或组织节点凭空编造关联。

## 3. 标准操作

1. 选择数据类型并下载标准模板；
2. 上传 `.xlsx`、`.xls` 或 `.csv` 文件；文件只上传一次，由服务端保存、解析并生成文件哈希；
3. 检查自动字段映射，必要时手工调整；预览时直接读取已保存源文件，不再由浏览器发送整表 JSON；
4. 选择重复数据处理策略：存在则更新、存在则跳过、只允许新增；
5. 点击“预览校验”；
6. 检查新增、更新、跳过和错误数量；
7. 对明确无效的错误行，可勾选后跳过并重新校验；
8. 错误清零后执行正式迁移；
9. 在迁移批次中检查进度和结果；
10. 需要修复时下载错误明细，按原始 Excel 行号修改后重新上传。

## 4. 校验与防重复

- 自动校验必填字段、手机号、身份证号、日期、整数、金额和枚举值；
- 同一文件内唯一标识重复时，所有重复行都会报错，不按最后一行覆盖；
- 相同模板与相同文件哈希不会重复创建迁移批次；
- 每一行保留原始行号、原始数据、标准化数据、处理动作和错误原因；
- 部分失败批次可继续执行，已成功行不会再次写入。

## 5. 撤销规则

正式迁移后可按批次撤销：

- 本批新增的数据会尝试删除；
- 本批更新的数据会恢复到迁移前快照；
- 已被后续业务引用的数据可能无法删除，系统会保留失败原因，不进行强制破坏性删除；
- 撤销只针对该批次产生的变更，不影响其他批次。

## 6. 大批量迁移与源文件规则

- 单个文件最多支持 10 万行、500 列；上传大小默认受系统 `MAX_UPLOAD_MB` 配置控制，当前建议 20MB 起步并按真实文件调整；
- 文件在服务端分批写入预览结果，每 500 行落库一次，避免一次性创建超大数据库请求；
- 页面最多展示前 500 行预览，但汇总、校验和正式迁移覆盖完整文件；
- 原始文件与哈希保留在迁移批次中，便于审计、重新预览和核对；同一模板和同一文件已经提交后不能重复迁移；
- 每批建议控制在 5,000 至 20,000 行，便于定位异常和重试；
- 先用 100 至 500 行真实结构的脱敏数据试跑；
- 迁移前保存原始文件只读副本和文件哈希；
- 正式迁移前后分别核对总人数、项目数、供应商数、在职人数和工资总额；
- 附件迁移不混入普通 Excel 行，应使用附件清单和独立文件包处理。
